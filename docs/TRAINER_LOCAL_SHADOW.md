# Локальный теневой режим тренера

24 октября 2026. Первый opt-in мост от режима тренера к исследовательскому
исполнителю. Флаг по умолчанию выключен. Советы игроку не заменяются.

## Что подключено

`/api/hand/analyze` по-прежнему получает и возвращает обычный `HandAnalysis`
текущего DecisionEngine. После расчёта совета локальный мост может поставить
подготовку отдельного исследования в очередь. Ответ не ждёт подготовки
публичных диапазонов, построения дерева, C++-обучения или проверки качества.

Изменения состояния тренера передаются наблюдателю при сериализованных
операциях с таблицей. Новый ход/улица/раздача отбрасывает старую подготовку
и инвалидирует результат. Долгое вычисление обычной подсказки тоже может
устареть: такой снимок не отправляется в теневую очередь.

Для профилей используется существующий `training_owner`. Локальная тестовая
сессия имеет отдельный контекст. Контекст в диагностике заменяется хешем.
Комнаты игры с друзьями и внутренние решения AI-оппонентов не подключены.

## Отключение по умолчанию и жизненный цикл

Нужно явно задать **оба** параметра при запуске локального backend:

```bash
export POKER_LOCAL_TRAINER_SHADOW=1
export POKER_LOCAL_TRAINER_SHADOW_PLAN=/absolute/path/to/plan.json
PYTHONPATH=backend backend/.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Флаг читается при старте приложения; файл плана загружается один раз.
Без флага research/native-модули даже не импортируются, потоки/процессы
исследования не создаются. `.env`, настройка работающего сайта и Render
этим изменением не включались.

Неверный/отсутствующий план отключает функцию и пишет только стабильный код
`LOCAL_TRAINER_SHADOW_DISABLED_INVALID_PLAN`. Подсказки продолжают работать.
Файл ограничен 1 МиБ. При завершении приложения мост и исполнитель закрываются
через threadpool, отдельно от event loop. Уже начавшаяся подготовка диапазонов
в потоке может закончиться до закрытия; принудительное прерывание этого потока
не реализовано. Её результат после закрытия не ставится в очередь.

Текущий production Dockerfile копирует только `app`, без research/native.
На нём этот режим не становится доступным от одной переменной окружения:
если исследовательского пакета нет, функция отключается. Серверный деплой
и сборка C++ для Render — отдельная работа.

## Политика для неперечисленных риверов

Добавлена конфигурация версии 2 и отдельная команда локального включения:
[флаг, seeded-подмножества и ограничения устойчивости](SOLVER_PUBLIC_SUBSET_POLICY.md).
Этот режим работает без ручного перечня ключей, но допускает только диагностику.
Проверка показала чувствительность к выбранным диапазонам; советы не заменяются.
Следующий раздел описывает прежние точные планы версии 1.

## Явные планы решений

План версии 1 содержит до 256 конкретных публичных ключей:

```json
{
  "version": 1,
  "limits": {"iterations": 100, "wall_seconds": 10, "memory_mib": 128, "quality_gate_pct_pot": 0.5},
  "decisions": {
    "PUBLIC_INFORMATION_KEY_SHA256": {
      "selected_hands": {"hero": ["AhAd", "3h3d"], "villain": ["KhKd", "5h5d"]},
      "input": {"bet_sizes": [13, 40], "raise_sizes": [80], "max_raises": 1, "utility_storage": "compact"}
    }
  }
}
```

Ключ в примере нужно заменить настоящим 64-значным `information_key` публичного
снимка. Перечень диапазонов должен покрывать ровно живые места, включая
`villain_2` и далее, если они участвуют. Веса берутся из публичной модели.
Полные диапазоны не обрезаются автоматически. Пробная рука — действительно
известные две карты героя; она должна уже входить в явно выбранный диапазон
и иметь совместимые раскладки. Порядок карт сопоставляется канонически.
Карты соперников не подставляются из игрового состояния.

Поддерживается только незавершённый ривер, когда ход у героя. Другие улицы
дают `UNSUPPORTED_DECISION`, отсутствие плана — `NO_EXPLICIT_PLAN`, отсутствие
руки в выборе — `OWN_HAND_NOT_SELECTED`. Это преднамеренная граница этапа.
На обычных случайных раздачах большинство снимков **не совпадёт** с заранее
подготовленными планами и будет пропущено. Этот режим сейчас предназначен
для воспроизводимых исследовательских состояний, а не для общего покрытия игры.

Расширение покрытия реализовано отдельной явной политикой версии 2; её
устойчивость к выбранным диапазонам пока не подтверждена. Добавление истинных
карт соперников или скрытая замена диапазона единственной рукой недопустимы.

## Границы данных и очередей

На пути запроса делается небольшой публичный снимок для проверки ревизии;
это синхронная сериализация, а не нулевая добавленная задержка. Закрытые карты
соперников исключаются **при сериализации**, а не копируются в фон и удаляются
позже. Имена заменяются id, заметки и колода не передаются. В фоне остаются
только публичное состояние и известная рука героя.

Полный `prepare_solver_snapshot`, проверка плана и постановка солвера выполняются
в отдельном потоке подготовки. По умолчанию ограничены:

- 32 контекста профилей/локальной сессии;
- 8 ожидающих подготовок и одна текущая;
- 256 событий моста в памяти;
- прежние ограничения исполнителя: один активный расчёт и два ожидающих.

При переполнении возвращается диагностический отказ. Можно освободить старый
неактивный контекст, но занятые контексты не вытесняются для нового профиля.
Подготовка повторно сверяет ревизию перед постановкой. Повторное получение
той же подсказки в той же ревизии не запускает новый расчёт. После отклонения
из-за отсутствия плана нужно новое состояние/перезапуск плана; автоматической
перезагрузки файла и бесконечных повторных попыток нет.

## Что записывается в сравнение

При `ready` контрактного результата журнал получает:

- обычное действие тренера и его точный размер;
- представлен ли этот размер в явно заданном дереве;
- наиболее вероятные действия обученной смешанной стратегии;
- вероятность совета тренера в этой стратегии;
- измеренное качество ограниченного расчёта;
- `live_advice_allowed: false`.

Размер не округляется к ближайшему. Если его нет в дереве, сравнение помечается
несопоставимым, вероятность/совпадение — `null`. Здесь сравниваются **частоты**,
а не EV или доказанная сила действия. Для отдельного EV-сравнения остаётся
[офлайн-корпус](SOLVER_COACH_COMPARISON.md).

Диагностика ограничена памятью процесса. Внутри локального backend доступна
`app.services.trainer_shadow.local_diagnostics()`; это Python-функция, не HTTP-
маршрут. Возвращаются состояние моста, события и журнал исполнителя. При
отключённом режиме — `{"enabled": false}`. Запись на диск, диагностический UI
и публичный доступ к чужим сессиям не добавлены.

## Проверки

[Сквозной отчёт](research/trainer-local-shadow-2026-10-24.json) создан через
настоящую функцию маршрута тренера и C++-процесс на фиксированной раздаче:

- ответ полностью совпал с прежним DecisionEngine;
- подготовлен публичный снимок, найден точный план;
- после ответа появился допущенный результат и сравнение;
- изменение состояния было замечено, прежний результат инвалидирован;
- завершение оставило ноль активных/ожидающих процессов.

В этом примере тренер предложил `BET 13`, наиболее вероятное действие в
ограниченной модели — `BET 40`. На сайте остался прежний `BET 13`. Это наблюдение
о конкретных выбранных диапазонах и дереве, не основание объявить совет ошибкой.
Измеренное время функции маршрута включает сам обычный анализ; отчёт не
сравнивает чистый overhead моста и не обещает задержку веб-запроса.

Юнит-тесты проверяют отключение без research-импортов, заблокированную фоновую
подготовку без ожидания в `/analyze`, отмену после хода, приватность, лимиты,
повторную подсказку, отсутствие плана, ошибки hook-ов, изоляцию профилей через
настоящие API-функции и запуск/завершение через lifespan.

```bash
PYTHONPATH=backend backend/.venv/bin/python backend/research/build_native.py
PYTHONPATH=backend backend/.venv/bin/python -m research.benchmark_trainer_shadow
PYTHONPATH=backend backend/.venv/bin/python -m unittest discover -s backend/tests -p test_trainer_shadow.py
```

## Следующий шаг

Расширить исследование за пределы заранее подготовленных снимков: явная,
воспроизводимая политика выбора диапазонов для обычных риверов, сравнение её
с более широким расчётом и проверка времени/памяти. До этого теневой режим
остаётся ограниченным локальным инструментом; советы, фронтенд, подписка и
размещение нового вычислителя не меняются.

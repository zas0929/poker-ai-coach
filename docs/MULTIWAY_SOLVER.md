# Солвер на 1–5 оппонентов: подготовка и выбор поставщика

Обновлено: 24 октября 2026.

## Требование

Целевой разбор — hero + 1–5 соперников, то есть 2–6 игроков, включая
постфлоп с 4–6 живыми участниками. Набор независимых heads-up решений не
заменяет общий multiway solve. Подготовка данных на шесть игроков не означает,
что найден или подключён решатель на шесть игроков.

TexasSolver из предыдущего эксперимента остаётся локальным heads-up эталоном.
В его проверенной реализации `PCfrSolver` число игроков задано равным двум.
Он не является целевым multiway-поставщиком.

## Что реализовано

`backend/app/services/solver_snapshot.py` готовит публичный снимок решения
для стола на 2–6 игроков, на любой обычной улице:

- Полный борд, текущий банк, блайнды, баттон, места и очередность после флопа.
- Отдельные стеки, ставки улицы и взносы за всю руку; нет сведения нескольких
  неравных стеков к одному «эффективному стеку».
- Сохранение фолднувших мест и их мёртвых денег; all-in остаются живыми участниками.
- Полная публичная история. Суммы помечены как `amount_added`: это добавленные
  фишки, а не итоговая ставка raise-to. Конкретный solver-adapter должен перевести
  их в свой формат и проверить достижимость узла в дереве.
- Полные публичные диапазоны каждого живого игрока, включая hero. На префлопе
  по 1 326 комбинаций, на ривере по 1 081 до пересечения с другими диапазонами.
  Диапазоны не обрезаются до 100 комбинаций ради ограничений старого probe.
- Ключ публичного информационного состояния. Смена любых закрытых карт,
  порядка колоды, имён или заметок не меняет экспорт и его ключ.

`RangeService.infer_public` не исключает реальную руку hero из диапазонов других
игроков. Его известные карты — только борд. После решения нужно отдельно
выбрать фактическую комбинацию hero из общей стратегии. Это предотвращает
передачу его закрытой руки моделируемым оппонентам.

Диапазоны по-прежнему эвристические, не GTO. Экспорт не исправляет калибровку
диапазонов и не моделирует влияние сброшенных карт (card bunching). Совместные
раскладки без коллизий должен учитывать настоящий multiway-провайдер.

`solver_availability` всегда сообщает `can_solve=false`: лицензированный рабочий
поставщик не настроен. Возможности кандидата и локального двухстороннего probe
отделены от факта доступности решения. Нет скрытого уменьшения числа игроков,
вызова солвера, внешнего API, нового endpoint или изменения подсказок на сайте.

## Как проверить на своём снимке

Нужен локальный JSON HandState **в момент решения**, не финальный итог руки.
Сохраняются только публичные поля и диапазоны, имена/закрытые карты/колода не экспортируются.

```bash
PYTHONPATH=backend backend/.venv/bin/python \
  backend/research/export_solver_snapshot.py /tmp/decision.json > /tmp/solver-input.json
```

Ввод должен содержать взносы всех мест, совпадающие с банком, живого текущего
игрока и борд своей улицы. Финальные руки, неизвестные участники/улицы,
отрицательные суммы и отсутствующие взносы отклоняются. Это структурная
подготовка существующего игрового снимка, не доказательство корректности
произвольной присланной истории: будущий web-endpoint обязан брать состояние
на сервере с проверкой доступа и верифицировать replay/переходы конкретного дерева.

## Проверенные публичные варианты

| Решение | Что подтверждено источником | Соответствие нашей цели |
| --- | --- | --- |
| TexasSolver | Проверенный локально heads-up river CLI | Только эталон для двух игроков |
| MonkerSolver | Производитель заявляет Hold'em/Omaha с любой улицы и любым числом игроков; GUI и минимум 8 GB RAM | Кандидат для 2–6; API/CLI, серверная лицензия и реальная нагрузка ещё не подтверждены |
| Simple 3-way | Постфлоп для трёх игроков | Не покрывает 4–6 живых игроков |
| GTO Wizard | До 9 игроков на префлопе; в опубликованных ограничениях постфлоп до 3 игроков | Подтверждённого покрытия 4–6 postflop нет |
| GTO Wizard partner API | GTO Score и FairPlay, отдельные партнёрские credentials | Наличие этих API не доказывает доступ к произвольному custom multiway solve |

Первичные источники (проверены 24.10.2026):

- [MonkerSolver](https://www.monkerware.com/solver.html),
  [руководство](https://www.monkerware.com/guide.html).
- [Simple 3-way](https://www.simplepoker.com/en/Solutions/Simple_3-way).
- [GTO Wizard: multiway и ограничения](https://blog.gtowizard.com/gto-wizard-ai-custom-multiway-solving/).
- [Официальные партнёрские API GTO Wizard](https://developers.gtowizard.com/).

Найденные публичные страницы Monker описывают GUI и сохранение решений, но по ним
не подтверждены программный интерфейс, возможность Linux-размещения или право
продавать рассчитанные разборы. Покупка desktop-лицензии сама по себе не решает
эти вопросы. Обещанный исследовательский API GTO Wizard не принимаем за уже
доступный коммерческий custom-solve API.

## Следующее условие реального подключения

Сначала получить подтверждение подходящего поставщика, затем интегрировать
конкретный протокол. Предпочтительный кандидат для проверки требований — Monker.
Сообщения поставщикам не отправлялись, покупки не выполнялись.

Подготовленные вопросы производителю:

1. Есть ли поддерживаемый API/CLI или пакетный режим для Hold'em на 2–6 игроков
   со всеми шестью живыми на флопе/тёрне/ривере, не только 6-max префлоп?
2. Можно ли передать отдельные диапазоны, разные стеки, side pots, историю
   и фактические размеры ставок, получить частоты и EV каждой руки/действия?
3. Разрешает ли лицензия размещение на нашем сервере, выдачу сохранённых
   разборов подписчикам, кэширование результатов и многопользовательскую очередь?
4. Поддерживается ли Linux/headless; какие лимиты одновременных задач, память,
   время расчёта и показатели качества доступны на 3-, 4-, 5-, 6-way postflop?

После подтверждения: тесты 2–6 реальных сценариев, корректное дерево и replay,
проверка совместимых диапазонов и побочных банков, лимиты ресурсов, серверная
очередь и кэш. До этого приложение продолжает явно эвристический анализ.
Собственный полноценный multiway-солвер — отдельная исследовательская разработка,
а не расширение параметра `player_number` в TexasSolver.

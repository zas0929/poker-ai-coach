# Контракт допуска исследовательского анализа

24 октября 2026. Версия контракта 1. Реализация: `research.analysis_contract`.
Боевой API, подсказки и UI не изменены.

## Назначение и вход

`analyze(request, ResearchLimits(...))` запускает ограниченный риверный анализ
в отдельном процессе и возвращает единый JSON-результат. Успешный расчёт можно
использовать для офлайн-исследования; он не разрешает заменить подсказку на сайте.

Запрос содержит **ровно** четыре поля:

```json
{
  "snapshot": "публичный schema-v1 объект prepare_solver_snapshot",
  "selected_hands": {"hero": ["AhAd"], "villain": ["KhKd"]},
  "own_hand": "AhAd",
  "input": {
    "bet_sizes": [10, 40],
    "raise_sizes": [80, 120],
    "max_raises": 1,
    "max_joint_combos": 4096,
    "utility_storage": "compact"
  }
}
```

Здесь `snapshot` показан описательной строкой ради компактности; в настоящем
запросе нужен полный объект. Выбор рук должен покрывать всех живых игроков.
`own_hand` — явно заданная пробная рука **текущего актора**, а не обязательно
игрока с id `hero`. Требуется точная запись комбинации из поддержанного
подмножества и хотя бы одна совместимая совместная раскладка.

Принимаются только публичные поля снимка, игроков и истории. Случайно
приложенные `cards` игрока, имена, колода или произвольные поля не игнорируются,
а дают `invalid_input`. Поле `cards` внутри публичной строки диапазона допустимо:
оно описывает возможную комбинацию, а не известные закрытые карты соперника.
Хеш снимка проверяется адаптером внутри ограниченного процесса. Это контроль
целостности, а не подпись отправителя.

## Поддержка и бюджеты

Поддерживаются schema-v1 ривер, 2–6 исходных мест, публичная модель
`public_action_heuristic_v1`, явные подмножества диапазонов, начало и уже начавшаяся
торговля, фолды, олл-ины и побочные банки в границах существующего прототипа.

Лимиты по умолчанию:

- 100 итераций native CFR+;
- 10 секунд процесса и 128 МиБ RSS;
- качество не хуже 0,5% банка текущей точки решения;
- 64 исходных сочетания по умолчанию; увеличение до 4096 указывается явно;
- до 20 000 узлов и одного миллиона пар «узел / совместимая раскладка»;
- компактные выплаты, до четырёх размеров открытия/рейза и трёх будущих рейзов.

Время, память и качество задаются через `ResearchLimits`. Нельзя ослабить порог
качества выше 0,5%; можно сделать его строже. Положительные конечные значения
и целое число итераций проверяются без преобразования bool/строк в числа.
Размеры ставок, лимиты и число будущих рейзов сохраняются в результате.

Native-библиотека должна быть явно собрана заранее. Проверку её манифеста,
исходников, бинарного хеша и ABI выполняет native-мост при загрузке. Контракт
не компилирует библиотеку автоматически и не переключает расчёт на Python
при её отсутствии.

## Формат результата

| Поле | Значение |
|---|---|
| `contract_version`, `scope` | Версия 1, `offline_bounded_river` |
| `status`, `reasons` | Итог и машиночитаемые причины с этапом проверки |
| `request_key` | Хеш публичного запроса, пробной руки и конфигурации дерева |
| `source_information_key` | Идентификатор публичной точки решения |
| `task_key` | Идентификатор фактически построенной задачи; до построения может отсутствовать |
| `provenance` | Версия движка, хеш ключевых исходников, версия/хеш модели диапазонов, метод и хранение выплат |
| `limits` | Запрошенные итерации, бюджет и порог качества |
| `timing` | Wall, время этапов, опрошенный/итоговый RSS; неизвестное — `null` |
| `model` | Публичные диапазоны/ограничения, восстановленная торговля, размеры и ресурсные параметры дерева |
| `quality` | Метрика, измеренное значение, порог, итог и исходные payoff/лучшие ответы |
| `candidate` | Стратегия только при `ready`; во всех остальных случаях `null` |
| `admission` | Разрешение офлайн-анализа; `live_advice_allowed` всегда `false` |
| `fallback` | Указание сохранить уже доступный совет текущего тренера |

Кандидат содержит id актора, его пробную руку, список точных действий и
нормированные вероятности, число совместимых раскладок этой руки и её условную
массу. Это смешанная стратегия, а не принудительно выбранная кнопка.

`fallback` — инструкция будущему вызывающему коду, а не вызов DecisionEngine.
Контракт сам не запрашивает новую подсказку, не заменяет текущую и не блокирует
игровые действия. В этом этапе он вообще не подключён к игровому маршруту.

## Статусы и причины

| Статус | Когда возникает | Примеры кодов |
|---|---|---|
| `ready` | Полное совпадение идентичности, качество и бюджеты пройдены | причин нет |
| `invalid_input` | Нарушен внешний публичный формат | `INVALID_PUBLIC_REQUEST` |
| `unsupported` | Улица, модель, состояние, дерево или пробная рука не поддержаны | `UNSUPPORTED_MODEL`, `UNSUPPORTED_STATE_OR_TREE`, `UNSUPPORTED_OWN_HAND` |
| `stale` | Сменился ключ публичного решения | `STALE_DECISION` |
| `quality_rejected` | Измеренный лучший ответ не прошёл порог | `QUALITY_GATE_FAILED` |
| `budget_exceeded` | Превышено время или память | `TIME_BUDGET_EXCEEDED`, `MEMORY_BUDGET_EXCEEDED` |
| `unavailable` | Нет пригодной native-библиотеки | `NATIVE_KERNEL_UNAVAILABLE` |
| `error` | Сломан монитор, процесс, идентичность или доказательства результата | `RESOURCE_MONITOR_FAILED`, `WORKER_FAILED`, `RESULT_IDENTITY_MISMATCH`, `INVALID_TREE_EVIDENCE`, `INVALID_QUALITY_EVIDENCE`, `INVALID_CANDIDATE` |

Завершённый процесс не получает допуск только по числу итераций или флагу
«качество пройдено». Родитель проверяет конечные числа, согласованность payoff,
лучших ответов, суммы улучшений и процента от банка; версию, запрос и источник;
параметры/размер дерева; нормировку стратегии и принадлежность нужной руке/актору.
Список действий, их порядок и точные размеры повторно сверяются с публичным
replay корня, включая право рейза после коротких олл-инов.
Неполные, NaN/Infinity или несогласованные данные не становятся рекомендацией.

Монитор RSS мягкий, с опросом 0,2 с, дополненный high-water RSS процесса.
После завершения повторно проверяются итоговый wall и память: выход между
опросами не отменяет лимит. Очень малый таймаут может фактически остановить
процесс позже заданной границы из-за запуска/опроса/завершения процесса; результат
при этом отвергается. Это не гарантия жёсткой задержки веб-запроса или лимит ОС.
Подготовка публичного снимка, сериализация и предварительная проверка вне
измеряемого процесса; сеть и пробуждение Render тоже не измеряются.

## Устаревание при асинхронной работе

`expected_source_key` проверяет соответствие до запуска. После расчёта вызывающий
код обязан сверить результат с **текущим** публичным состоянием:

```python
result = analyze(request, expected_source_key=key_before_start)
result = recheck_decision(result, current_source_key=latest_public_key)
```

При смене ключа `recheck_decision` возвращает копию со статусом `stale`, кодом
`STALE_DECISION`, этапом `delivery` и пустым кандидатом. Исходный результат
не меняется, отклонённый результат никогда не повышается до `ready`.
Сам контракт не наблюдает за живой комнатой и не получает её состояние автоматически.

## Проверки и воспроизведение

[Сохранённый отчёт](research/river-analysis-contract-2026-10-24.json): 12/12
контрольных исходов совпали с ожидаемыми. Реальные дочерние процессы проверили
готовность на 2 и 6 местах, провал качества, время, память, повреждённый снимок,
руку вне подмножества и отсутствие native-библиотеки. Отдельно проверены
предварительное устаревание, смена решения после расчёта, случайные скрытые данные
и неподдержанная улица. В каждой отказной ветке кандидат отсутствует, живые
подсказки запрещены к замене, текущий тренер сохраняется.

Шестиместный пример содержит по три возможные руки на место, 729 исходных /
146 совместимых раскладок. Допуск получен примерно за 6,1 с, с итоговым RSS
43.6 МиБ и отклонением 0,175437% банка. Это исследовательское измерение,
а не обещанная задержка на сайте.

```bash
PYTHONPATH=backend backend/.venv/bin/python backend/research/build_native.py
PYTHONPATH=backend backend/.venv/bin/python -m research.benchmark_contract
PYTHONPATH=backend backend/.venv/bin/python -m research.analysis_contract request.json --wall-seconds 10 --quality-gate 0.5
PYTHONPATH=backend backend/.venv/bin/python -m unittest discover -s backend/tests -p test_analysis_contract.py
```

Юнит-тесты дополнительно вносят ложную идентичность, неверный размер дерева,
неполную стратегию, несогласованный/нечисловой лучший ответ и превышение бюджета
после последнего опроса. Транспортный unit-тест подменяет обучение Python-эталоном;
отдельный отчёт реальных процессов использует явно собранное C++-ядро.

# Упаковка ограниченного разбора для staging

Сервис: `poker-ai-coach-api`, workspace `poker-ai-coach`, прежний бесплатный
Render web service. Контекст сборки — `backend/`, Dockerfile — `backend/Dockerfile`.
Новые сервисы, платные планы и базы данных не создаются.

## Образ

- В отдельной стадии компилируется существующий C++17 native-код для платформы
  деплоя. Библиотека и её манифест попадают в `/opt/poker/native/`.
- Runtime содержит `app/`, `research/`, `libstdc++6` и `procps` для наблюдения RSS.
  Компилятор в runtime не копируется; запрос не запускает сборку.
- Последний шаг сборки `python -m research.verify_packaged` проверяет ABI,
  флаги, SHA исходника/бинарника, затем все пять моделей через настоящий
  изолированный процесс, проверку качества и EV. База и секреты ему не нужны.
- Сохраняется один uvicorn worker. Очередь решателя имеет одного владельца;
  ограничения — 300 итераций, 10 секунд, 128 MiB наблюдаемой RSS, две ожидающие
  задачи, 64 комбинации и 4000 узлов. RSS — наблюдаемый мягкий предел, не cgroup.
- `.dockerignore` допускает только нужные исходники, исключает локальные базы,
  `.env`, Python-кэш и локальные платформенные бинарники.

## Включение

В Render с сохранением остальных переменных:

```text
POKER_RIVER_LESSONS_ENABLED=1
POKER_RESEARCH_NATIVE_LIB=/opt/poker/native/libpoker_cfr.so
```

Старый `POKER_LOCAL_RIVER_LESSONS=1` продолжает работать для локального запуска.
Новый флаг имеет приоритет: явный `0` выключает функцию, даже если старый равен `1`.
По умолчанию функция выключена и research-модули не импортируются приложением.
При включении библиотека проверяется **до** создания очереди. Отсутствующий или
несовместимый бинарник оставляет режим недоступным, основной сервер продолжает
обслуживать игру; каталог сообщает `LESSON_ENGINE_UNAVAILABLE`.

После выкладки требуется проверить именно новый commit и статус `live`, затем
каталог с `enabled: true`, закрытые операции без профиля (401), примеры и собственные
задачи через Bearer-токен. Отдельная проверка — сохранённые завершённые решения
на staging. Деплой с рабочим HTTP-портом сам по себе этого не подтверждает.

База остаётся существующей Supabase private схемой. В ней индекс завершения
создаётся идемпотентно; старые решения без отметки завершения не импортируются.
Задачи расчёта хранятся в памяти и после перезапуска требуют повторного запуска.
Бесплатный сервер может засыпать; холодный старт не считается скоростью солвера.

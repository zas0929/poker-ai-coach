# Индексированный обход CFR+

24 октября 2026. Ускорение исследовательского прототипа, не игровых подсказок сайта.

## Изменение

Добавлен метод `cfr_plus_indexed`, реализованный в `research/indexed_cfr.py`.
Он использует прежние дерево, совместные раскладки, выплаты и информационные
множества. Текущий `cfr_plus` сохранён как эталон; методы выбираются явно.

Перед обучением узлы и информационные множества получают плотные числовые
индексы. Для каждой раскладки один раз строятся связи с индексами информации
и терминальными выплатами. Во время рекурсивного обхода больше нет поиска
через `id(node)` и словари ключей из собственной руки/публичной истории.

Вместо копии списка вероятностей достижения на каждое ребро используется
один рабочий список: значение перед спуском сохраняется и после возвращения
восстанавливается. Буферы значений действий выделяются один раз на узел и
переиспользуются. Это безопасно для дерева с одним родителем у каждого узла;
компиляция отдельно проверяет это свойство. Для игрока без решений (например,
уже сфолдившего) пропускается пустой обучающий проход.

Сохраняются полный перебор шансов, порядок действий, заморозка политики на все
раскладки перед обновлением одного игрока, clipping сожалений и линейное
усреднение. Никакие руки, действия или ветки не удаляются, sampling не добавлен.
Это ускорение реализации, а не новый алгоритм/модель игры.

## Сравнение

Одинаковые 10 задач из [SOLVER_CAPACITY.md](SOLVER_CAPACITY.md), 100 итераций,
2–6 мест, неопределённость у каждого игрока, максимум 64 исходных сочетания.
Для каждого метода отдельный свежий процесс; методы запускаются последовательно,
их порядок чередуется между задачами. Тесты не запускались параллельно замерам.
Построение индексов **включено** во время обучения нового метода, тёплого кэша нет.

Из обоих процессов выгружена полная политика. Сопоставлены все информационные
ключи, числа действий и вероятности, затем выплаты и точные лучшие односторонние
ответы, рассчитанные прежним независимым от обучения `measure`.

- На 10/10 задачах максимальная разность вероятностей: **0**.
- Максимальная разность payoffs, лучших ответов и gains: **0**.
- Оба метода прошли исследовательский порог 0.5% банка на всех задачах.
- Проверка допускает 1e-10 для вероятностей и 1e-8 фишки для payoffs, но на
  выполненном наборе различия не понадобилось округлять до этих допусков.

## Проверки корректности

Помимо 10 полных сравнений на 100 итерациях, unit-тесты сопоставляют методы на
2–6 местах: несколько действий и повторные решения, взвешенные коллизии карт,
side pots, одиночные/суммарные короткие олл-ины, сфолдившие места, терминальный
олл-ин и повторное обучение того же объекта. Проверяются стратегии, payoffs и
лучшие ответы. Таймаут, другая информационная структура, другая вероятность
или другой лучший ответ не принимаются сравнителем за успешное совпадение.

Проверка эквивалентности сохраняет качество прежнего исследовательского CFR+;
она не добавляет гарантии сходимости для 3+ игроков или сертификата полного NLHE.

## Воспроизведение

Из корня репозитория:

```bash
PYTHONPATH=backend backend/.venv/bin/python backend/research/benchmark_indexed.py --iterations 100 --timeout-seconds 45 --check
PYTHONPATH=backend backend/.venv/bin/python backend/research/custom_river.py --players 2 3 --iterations 200 --method cfr_plus_indexed --bet-sizes 25 50 --raise-sizes 100 --max-raises 1
PYTHONPATH=backend backend/.venv/bin/python -m unittest discover -s backend/tests -p test_indexed_cfr.py
```

Публичный снимок также можно запустить с `--method cfr_plus_indexed`:

```bash
PYTHONPATH=backend backend/.venv/bin/python backend/research/river_snapshot.py /tmp/snapshot.json --selected-hands /tmp/hands.json --method cfr_plus_indexed --bet-sizes 10 --iterations 200
```

В Python: `game.train(100, method='cfr_plus_indexed')`. Результат имеет тот же
формат политики, пригодный для прежнего `game.measure(policy)`.

## Оставшиеся границы

Лимит 64 сочетания и остальные бюджеты не повышены. Полные диапазоны настоящей
раздачи пока недоступны. На шести местах всё ещё требуется около 10–18 секунд
обучения в этих малых задачах; для блокирующей подсказки на каждом ходе этого
недостаточно. Код остаётся в research, боевой тренер не переключён.

Следующий шаг — отдельно проверить более высокий бюджет рук с явными лимитами
времени/памяти и теми же метриками точных лучших ответов; решить по замерам,
когда полный перебор требует компилируемого цикла или sampling. Ускорение в
два раза само по себе не устраняет комбинаторный рост.


Контролируемое расширение бюджета проверено следующим этапом:
[SOLVER_EXPANDED_RANGES.md](SOLVER_EXPANDED_RANGES.md). Значение 64 по умолчанию
сохранено; новый более высокий бюджет доступен явно, ресурсные границы и
неудачные случаи опубликованы отдельно.

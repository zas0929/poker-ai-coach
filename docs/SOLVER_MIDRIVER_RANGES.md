# Расширенные диапазоны внутри ривера

24 октября 2026. Офлайн-исследование; боевые подсказки и API не переключены.

## Методика

Добавлен `research.benchmark_midriver_ranges`: 16 фиксированных задач из
публичных schema-v1 снимков настоящего игрового движка. Точки находятся после
чеков/ставок/рейзов; отдельно представлены фолд на ривере, прошлый олл-ин,
одиночный короткий рейз без переоткрытия и накопленные короткие рейзы
с переоткрытием. Основной набор использует два борда и 2–6 мест.

У каждого живого места явно выбирается несколько комбинаций из его публичного
эвристического диапазона. Выбор детерминирован seed; веса сохраняются.
Настоящие закрытые карты не поступают адаптеру. Отбор не зависит от выигрыша
или известной руки героя. Сфолдившему месту диапазон не подставляется.

Каждая задача выполняется в отдельном процессе: адаптер/дерево/выплаты,
100 итераций native CFR+, точный лучший ответ в этом же ограниченном дереве.
Используется компактное хранение выплат. Будущие размеры — 10/40 для открытия,
80/120 для повышения, один будущий рейз; незаконные размеры отсутствуют в ветке,
размер ограничивается доступным стеком. Уже наблюдённые рейзы лимит не расходуют.

Порог — максимальное улучшение payoff одним игроком при переходе к лучшему
ответу **не более 0,5% текущего банка**. Это не сравнение с эталонным NLHE-солвером
и не проверка качества модели диапазонов. В игре на несколько участников сам
по себе CFR+ не гарантирует сходимость к равновесию.

На процесс выделены 45 секунд и 128 МиБ. RSS опрашивается через `ps` каждые
0,2 секунды; также проверяется high-water RSS самого процесса. Это мягкий
контроль с возможным превышением между опросами, не ограничение ОС.
Таймаут/переполнение/отказ не получают зачёт качества. Подготовка исходного
снимка и выбор подмножества происходят до запуска таймера процесса; сеть,
пробуждение Render и сборка C++ в измерение не входят. Wall включает запуск
Python, загрузку готовой библиотеки и задержку опроса наблюдателя.

## Результаты

Все **16/16** задач завершились и прошли порог на 100 итерациях.
Максимальное отклонение — **0,200913% банка**. Отказов и таймаутов нет.

[Полный отчёт](research/river-midriver-ranges-2026-10-24.json) сохраняет публичные
истории/стеки, выбранные руки и веса, source/task keys, восстановленную очередь,
время этапов и память. Полные исходные диапазоны воспроизводятся генератором,

Коллизии карт исключаются из совместных раскладок, а не заменяются новыми
руками. В отчёте `compatible_range_counts` показывает фактическую поддержку
после этого исключения. Во всех случаях у каждого живого игрока осталось
минимум две руки; например, в `short_reopened_4` одно место сохранило 3 из 4.
Это отличает проверки от задачи с единственной известной рукой на место.

В `six_729` из 729 исходных сочетаний совместимы 146, по 3 возможные руки у всех
шести мест. Построение заняло 1.937 с, обучение 1.280 с,
точный лучший ответ 2.509 с; полный процесс 6.124 с,
RSS 40.6 МиБ. Этот случай показывает, что после ускорения native
проверка качества и построение дерева остаются существенной частью затрат.

## Проверки реализации

[Парный отчёт](research/river-midriver-paired-2026-10-24.json): на `dry_3` и
`short_reopened_4` после 20 итераций Python indexed и C++ дали нулевое
расхождение вероятностей, payoff и лучших ответов. В тестах дополнительно
сверены все ветки нескольких задач с игровым движком, сохранение публичных
весов, воспроизводимость, право рейза и отказ на повреждённом снимке.

```bash
PYTHONPATH=backend backend/.venv/bin/python backend/research/build_native.py
PYTHONPATH=backend backend/.venv/bin/python -m research.benchmark_midriver_ranges
PYTHONPATH=backend backend/.venv/bin/python -m research.benchmark_midriver_ranges --paired --iterations 20
PYTHONPATH=backend backend/.venv/bin/python -m research.benchmark_midriver_ranges --cases six_729 --iterations 200
PYTHONPATH=backend backend/.venv/bin/python -m unittest discover -s backend/tests -p test_midriver_ranges.py
```

Последняя команда с 200 итерациями — пример отдельного повторного измерения;
в опубликованном основном отчёте использованы 100. Пустой, неизвестный или
повторённый список `--cases` вызывает ошибку до запуска процессов.

## Вывод для следующего этапа

Эти ограниченные состояния пригодны для дальнейшего **офлайн-сравнения** с
текущим тренером. Они ещё не основание автоматически заменить подсказки:
диапазоны эвристические и сильно сужены, дерево дискретное, полные диапазоны
1–5 оппонентов и будущие улицы не покрыты. Меньшее число узлов внутри ривера
не означает ускорение полного дерева с начала улицы.

Следующий шаг — офлайн-сравнение рекомендаций на фиксированном корпусе
публичных решений: текущий тренер против прототипа, с явным описанием
поддержанных состояний, размеров и качества расчёта. После этого можно
планировать теневой запуск с отдельным бюджетом задержки. Он не должен
задерживать доступные игровые действия.

# Аудит движка и локальный прототип солвера

Дата: 24 октября 2026. Статус: исследовательский этап, без подключения к сайту.

## Вывод

Свой игровой движок и оценщик оставляем. Независимая сверка не обнаружила ошибок
на выбранных комбинациях и контрольных эквити; она не доказывает правильность
стратегии. Основной стратегический пробел — эвристические диапазоны и выбор
действия по порогу эквити без сравнения EV линий.

TexasSolver удалось собрать и вызвать из Python на трёх синтетических риверах.
Получены настоящие частоты действий, проверены их вероятности и контрольные
исходы. Независимый перебор лучших ответов подтверждает сходимость в этих малых
деревьях. Это ещё не анализатор произвольной раздачи из приложения.

## Независимая сверка своего движка

`backend/research/audit_engine.py`, seed `20261024`, PokerKit `0.7.7`:

- 15 000 сравнений пар рук: по 5 000 для 5, 6 и 7 карт; расхождений нет.
- 20 взвешенных heads-up риверных диапазонов по 16 комбинаций: точное эквити
  совпадает с PokerKit с учётом округления нашего ответа до 4 знаков.
- Тёрн с фиксированной рукой соперника: независимый полный перебор 44 риверов
  дал 0.272727; наша оценка 10 000 симуляций — 0.2779, граница погрешности 0.0136.
- Многосторонний ривер: полный перебор совместимых комбинаций дал 0.111111;
  наша оценка — 0.1099 при той же границе 0.0136. Включена коллизия диапазонов,
  проверяющая отбор всей совместной раскладки, а не последовательное смещение.
- Локальная скорость собственного семикарточного score: около 178 тыс./с.
  Это одно измерение, не сравнительный бенчмарк библиотек и не серверный SLA.

Сырые измерения: [engine-audit-2026-10-24.json](research/engine-audit-2026-10-24.json).
Сверка выборочная, не исчерпывает все комбинации и не проверяет калибровку диапазонов.

Обнаружен и исправлен пробел валидации **явно переданных внешних диапазонов**:
NaN/бесконечные веса, заблокированные карты, повторы карт/комбинаций должны
отклоняться до расчёта. Проверка единая для heads-up и multiway; легальный
нулевой вес допускается при положительном конечном суммарном весе. Число
симуляций теперь требует положительного целого, bool и дроби не допускаются.
Внутренний RangeService уже генерирует корректные комбинации; это не свидетельство
того, что обычные раздачи сайта раньше считались с такими ошибочными диапазонами.

## Реальный прототип TexasSolver

Источник: https://github.com/bupticybee/TexasSolver, ветка `console`, commit
`6dfb65b4d7ed081da509e8d8c3d82138c4708267`.
Исходники, бинарник, ресурсы и JSON-деревья не входят в наш репозиторий.

Проверены три сценария:

1. Известные AA против QQ на безопасном ривере: слабая рука сбрасывает на обе ставки.
2. Общий роял-флеш: фолд не выбирается; колл и рейз могут быть равноценны.
3. Два синтетических взвешенных диапазона по 48 комбинаций: 2 118 совместимых
   раскладок. Это техническая нагрузка, не реалистичная модель игрока.

Вход: банк 100, эффективный оставшийся стек 100, два игрока, ривер без ранее
сделанных ставок на этой улице, без рейка. Ставки 50% банка и all-in, ограниченное
дерево повышений. Один поток, максимум 1 000 итераций, целевая точность 0.1% банка.
Скрипт проверяет фактически экспортированную ставку 50, а не только текст конфигурации:
upstream-параметр all-in threshold способен заменить запрошенный размер на all-in.

CLI экспортирует JSON с действиями и частотами. Таблицы EV каждого действия в
этом экспорте нет. Наш независимый обход дерева вычисляет среднюю выплату
экспортированной стратегии и лучшие ответы для **этих** явных риверных диапазонов.
Игрок при выборе лучшего ответа видит только свою руку и историю действий, а не
конкретную руку оппонента. Есть отдельный тест против такого подсматривания.

`strategy_payoff_ip_oop_chips` — нулевая сумма с исходным банком, условно
профинансированным поровну обоими игроками. Это не UI-показатель EV колла с
нулём на фолде. Независимая exploitability = сумма лучших ответов / (2 × банк).
Player 0 в upstream JSON — IP, player 1 — OOP. Сумма BET/RAISE в этом JSON —
**добавляемые** фишки; её нельзя напрямую передавать в наш API с `raise to`.

Замеры записаны в [solver-probe-2026-10-24.json](research/solver-probe-2026-10-24.json).
Три сценария одним процессом заняли **9.722 с** с загрузкой ресурсов;
пиковый RSS дочернего процесса — **131.3 MiB**. Upstream напечатал 0.003–0.005 с
на собственно решение этих маленьких деревьев. Независимая exploitability для
48×48 диапазонов — 0.05523296% банка против 0.055234432% в отчёте upstream.
Это измерение не включает время нашего последующего независимого обхода дерева.
Окружение: macOS, x86_64 бинарник
на arm64-хосте. Один запуск не устанавливает производительность Linux/Render.

## Как воспроизвести

Независимый аудит запускается в отдельном Python 3.11+ окружении. Основной backend
и его requirements не переводятся на новый Python и не получают PokerKit:

```bash
python3.11 -m venv /tmp/poker-audit-venv
/tmp/poker-audit-venv/bin/pip install -r backend/research/requirements-audit.txt
PYTHONPATH=backend /tmp/poker-audit-venv/bin/python backend/research/audit_engine.py
```

Солвер берётся и собирается отдельно по инструкции upstream. В проверенной локальной
копии потребовались только изменения сборки: deployment target 10.15 вместо 10.7;
исключение устаревших необязательных googletest/pybind11 и target test; явная линковка
TexasSolver с `${OpenMP_CXX_LIBRARIES}`. Логика солвера не менялась.
Установленный OpenMP: `/usr/local/opt/libomp`; команды конфигурации:

```bash
git clone --branch console https://github.com/bupticybee/TexasSolver.git /tmp/poker-texassolver
git -C /tmp/poker-texassolver checkout 6dfb65b4d7ed081da509e8d8c3d82138c4708267
# Применить перечисленные выше изменения сборки в этой локальной копии.
cmake -S /tmp/poker-texassolver -B /tmp/poker-texassolver/build-audit \
  -DCMAKE_BUILD_TYPE=Release -DCMAKE_POLICY_VERSION_MINIMUM=3.5 \
  -DOpenMP_C_FLAGS='-Xpreprocessor -fopenmp -I/usr/local/opt/libomp/include' \
  -DOpenMP_CXX_FLAGS='-Xpreprocessor -fopenmp -I/usr/local/opt/libomp/include' \
  -DOpenMP_C_LIB_NAMES=omp -DOpenMP_CXX_LIB_NAMES=omp \
  -DOpenMP_omp_LIBRARY=/usr/local/opt/libomp/lib/libomp.dylib
cmake --build /tmp/poker-texassolver/build-audit --target console_solver -j 2
PYTHONPATH=backend backend/.venv/bin/python backend/research/solver_probe.py \
  --binary /tmp/poker-texassolver/build-audit/console_solver \
  --resources /tmp/poker-texassolver/resources \
  --artifacts /tmp/poker-solver-artifacts
```

CLI выполняет три сценария одним процессом, имеет таймаут 120 секунд, сохраняет
входы/логи/сырые стратегии только при `--artifacts`. Нет web-endpoint, запуска на
Render, обращения к чужой комнате или изменения игровой стратегии приложения.
Это ограниченный локальный эксперимент, не production sandbox для произвольных задач.

## Решение о следующем этапе

Подключение технически возможно, но сначала нужно:

1. Проверить условия использования TexasSolver в платном онлайн-сервисе: upstream
   указывает AGPL-3.0 и отдельно обсуждает коммерческую лицензию. Локальный прототип
   не означает разрешение коммерческого размещения. Источник — README upstream.
2. После уточнения требований целевой режим — 2–6 игроков, в том числе multiway
   postflop. Готовится общий публичный формат и диапазоны каждого игрока.
   TexasSolver остаётся только heads-up эталоном; выбор multiway-поставщика
   описан в [MULTIWAY_SOLVER.md](MULTIWAY_SOLVER.md).
   Нельзя просто зафиксировать реальную руку hero как весь его диапазон: это
   сообщило бы модели соперника его руку. Нужна выборка результата для hero-комбо
   из решения полных диапазонов и обработка фактической истории улицы.
3. Протестировать более широкие диапазоны и ресурсы на Linux; решить, нужен ли
   постоянный процесс/очередь и кэш задач. Флоп и multiway пока не поддерживаются.
4. Сохранить источник анализа, параметры дерева, погрешность, версию солвера и
   допущения. Показывать «эвристика» там, где солвер неприменим, без ложного GTO.
5. Только затем добавить LLM-объяснения и проверить их численные утверждения.

Продуктовые договорённости для будущего AI-разбора: только зарегистрированные
пользователи; 3 бесплатных разбора, затем подписка. Предложение по единице учёта —
одна завершённая раздача целиком, сохранённый ответ открывается бесплатно, ошибки
не расходуют попытку. Период квоты, объём подписки и лимит уточняющих вопросов
нужно окончательно определить перед реализацией оплаты. В этом этапе auth,
платежи и AI API не добавлялись.

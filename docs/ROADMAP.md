# Poker AI Coach — roadmap

Обновлено: 21 октября 2026.

Цель первого онлайн-релиза: приватные столы на 2–6 друзей с виртуальными
фишками, входом по ссылке и восстановлением места после обрыва связи.

## 1. Правила heads-up — реализовано

- Правильная очередь действий на обеих позициях и всех улицах.
- Минимальная ставка, полный рейз и короткий all-in; защита от ставок сверх стека.
- Единый расчёт допустимых действий для движка, AI, тренера и UI.
- Возврат неуравненных ставок, корректное деление банка и нечётной фишки.
- Отклонение недопустимого действия до изменения состояния.
- Защита завершённой раздачи от повторного действия или выплаты.
- Повторный запрос `/start` возвращает незавершённую раздачу без сброса фишек.
- Контрольные тесты, включая 200 полных автоматически разыгранных рук.

Проверка: из `backend/` выполнить `PYTHONPATH=. .venv/bin/python -m unittest discover -s tests -v`.

Теперь движок поддерживает 2–6 игроков. API хранит одну тренировочную сессию в
памяти. Приватные комнаты используют отдельный API и SQLite: места, стеки, колоды
и незавершённые раздачи восстанавливаются после рестарта сервера.

## 2. Движок на 2–6 игроков — реализовано

- Места, движение баттона/блайндов, общий обход очереди.
- Основной и побочные банки; учёт взносов каждого игрока за всю раздачу.
- Несколько all-in и восстановление права рейза после полных повышений.
- Переходы между heads-up и столом с тремя и более игроками.
- Реальные AI-игроки на всех местах; смена размера стола между раздачами.
- Отдельная колода каждой раздачи и последовательное выполнение API-команд.
- Самостоятельный multiway-анализ: совместная выборка диапазонов без совпадения
  карт, разделение equity при ничьих, исключение сбросивших игроков.
- Разбор выплат по каждому банку. Побочные банки не используют упрощённый
  heads-up EV: он скрыт до реализации отдельного расчёта для каждого банка.

Проверено: контрольные сценарии основных/побочных банков, коротких all-in и
очереди, а также 500 случайных раздач на разных размерах стола. Новый размер
стола после окончания руки начинает новую учебную сессию со стеками по 1000.

Ограничения: соперники пока программные, диапазоны и рекомендации эвристические.
API тренировочного режима содержит закрытые карты всех AI. Игра с людьми использует
отдельные комнаты с персональными представлениями и идентификацией этапа 3.

## 3. Комнаты и серверная синхронизация — реализовано

- Отдельные состояние и колода каждой комнаты.
- Сервер проверяет команды и отправляет события по WebSocket.
- Персональное представление: клиент получает только свои закрытые карты.
- Версии состояния и защита от повторных/запоздавших команд.

Реализованы UI `/friends`, создание и вход по приглашению, имена, готовность,
раздача хозяином, автоматические переходы улиц и восстановление места.
Токен места передаётся в первом WebSocket-сообщении, в приглашении только код.
Карты скрываются на сервере; на showdown открываются карты не сбросивших игроков.

Проверено: 67 backend-тестов, два WebSocket-клиента и две вкладки UI.
Независимые столы не влияют друг на друга; повтор команды не повторяет ход.
Подробности и запуск: `docs/ROOMS.md`.

Ограничения: один процесс backend с локальной SQLite, хостинг ещё не настроен.

## 4. Удобство приватной игры — реализовано

- Уже есть: создание, приглашение, имена, автоматическое место и готовность.
- Готово: таймер хода 30 секунд, check/fold по таймауту и автоматический sit-out.
- Готово: выход, sit-out и возврат между руками; передача роли хозяина.
- Готово: новые участники между раздачами, сохранение стеков и движение баттона.
- Готово: восстановление места и статусы соединения; переподключение не продлевает ход.
- Готово: настройки стека, блайндов и времени хода до первой раздачи.
- Изменение настроек сбрасывает готовность; стартовый стек не меньше 20 BB.
- Адаптивные формы настроек. Дополнительная полировка мобильной игры — перед релизом.
- Проверено 75 backend-тестов, реальное истечение таймера через WebSocket.

## 5. Сохранение и восстановление — реализовано

- База комнат, участников, стеков и истории.
- Восстановление партии после перезапуска и журналирование событий.
- Проверка конкурентных команд, переподключений и повторных запросов.

SQLite хранит приватный снимок комнаты вместе с колодой, токенами мест и ID
подтверждённых команд. Состояние, журнал события и завершённая раздача записываются
одной транзакцией до ответа клиенту. Ошибка записи откатывает действие в памяти.
База исключена из Git; файл создаётся с доступом только владельцу.

Проверено: 87 тестов, включая отказ записи, конкурирующие команды и повтор после
рестарта. Реальный перезапуск процесса посреди флопа сохранил карты, стеки,
настройки и таймер, после чего раздача продолжилась на тёрне. Время простоя
учитывается в таймере; истёкший ход обрабатывается после запуска.

Ограничения: один backend-процесс; репликация, резервные копии и управление
жизненным циклом старых комнат относятся к подготовке онлайн-релиза.

## 6. Развитие тренера

- Разбор и повтор раздачи, история решений, упражнения по ошибкам.
- Размеры ставок и глубина стеков в диапазонах, эталонные решения для проверки.
- Отдельный явно обозначенный учебный стол; обычная игра с разбором после руки.
- LLM объясняет проверенные расчёты; не подменяет математический движок.

## 7. Закрытый онлайн-релиз

- Хостинг, HTTPS/WSS, конфигурация и наблюдение за ошибками.
- Реальная сессия с друзьями из разных сетей и устройств.
- Проверки нескольких комнат, коротких all-in, side pots и обрывов связи.

Публичное лобби, рейтинги, чат и сложный солвер не входят в первый релиз.

## Принятые правила ставок

Рейз задаётся общей суммой ставки на улице (`raise to`), а не добавляемой суммой.
Неполное повышение допускается только как all-in. API требует точного целого
числа фишек и отклоняет некорректную сумму вместо её молчаливого округления.
Для heads-up нечётную фишку при ничьей получает игрок слева от баттона.

Источники: [PokerStars: очередь и all-in](https://www.pokerstars.com/help/articles/poker-rules-master/217444/),
[Poker TDA: правила 21, 36, 45 и 49](https://www.pokertda.com/view-poker-tda-rules/).
Правила TDA используются как ориентир механики; это не заявление о полной
реализации турнирного регламента или правил живых словесных заявок.

# Объединение групп и перераспределение строк

Добавлен ограниченный диагностический прототип: он объединяет близкие стратегии,
проверяет результат в исходной игре и пробует потратить освобождённые строки на
новое разделение. На десяти выбранных известных случаях найден **один** ранее
отклонённый случай, который после перераспределения прошёл порог. Это проверка
гипотезы, а не готовый алгоритм для включения в тренере.

## Механика

Исходная политика получается прежним `train_adaptive_indexed`. Разбиение рук
восстанавливается по сохранённой трассе разделений и проверяется по конечному
числу строк. Для пар групп одного места вычисляется максимальный TV их
стратегий по общим публичным историям. Исходная политика обязана выбирать
одинаковые частоты для всех рук каждой группы.

Группы сортируются по сходству, затем по числу освобождаемых строк, с
детерминированными разрешениями равенств. TV ≤0,1 служит только предварительным
фильтром. Проверяются максимум два первых кандидата. Число освобождённых строк
равно числу историй, общих двум группам.

При объединении новая стратегия — среднее исходных частот с весами исходной
маргинальной массы каждой собственной руки. Масса считается по всем допустимым
совместным раздачам, включая исходные блокеры и веса. Это выбор способа проекции
политики, а не новая модель раздачи. Он не учитывает достижимость текущей истории
как дополнительный вес, поэтому сходство само по себе не гарантирует сохранения
выгод действий. Карты и веса раздач не заменяются представителями.

Объединённая политика полностью оценивается в исходной игре, где лучший ответ
различает настоящие руки. Если максимальный unilateral gain вырос больше чем
на числовой допуск 1e−10 процентного пункта банка, кандидат отклоняется без
повторного разделения. Этот критерий строже простого прохождения порога 0,5%:
объединение может остаться внутри порога, но всё равно быть отклонено как ухудшение.

После неухудшающего объединения ищется одно разделение по ранее исследованному
приоритету места с наибольшей ошибкой. Простой возврат к исходному разбиению
распознаётся по составу групп независимо от их имён и отклоняется. Если новое
разбиение действительно другое, оно обучается заново 100 итераций и проверяется
лучшим ответом в исходной игре. Бюджет строк остаётся прежним: не больше 75%
исходной полной таблицы, максимум 8 групп на место. Финальный порог — ≤0,5% банка.

Это дополнительная работа поверх базового уточнения, а не сравнение при
одинаковом количестве обучений: явный дополнительный бюджет — два пробных
объединения и максимум одно переобучение на каждое. Общий внешний процесс
по-прежнему ограничен 45 секундами и 128 MiB. Автоматического выбора такой
политики для ответа пользователю нет.

## Результаты 24 октября 2026

[Отчёт](research/group-reallocation-2026-10-24.json) сохраняет все кандидаты,
метрики объединения, разницу ошибки, попытки повторного разделения, ограничения
и хеши исходников. Выбраны десять известных случаев, включая два простых
положительных контроля. Это не независимая выборка и не оценка частоты успеха
на всех столах.

Девять задач завершились. В `short_raises_6_101` процесс остановлен примерно
через 45,2 секунды уже на этапе `merge_audit`; финальный результат аудита не
допущен. Новый этап пока добавляет заметную стоимость к базовому расчёту.

Из девяти завершённых задач в пяти ни одна пара не прошла фильтр сходства.
В остальных четырёх задачах проверены шесть объединений:

| Случай | Кандидатов проверено | Результат |
|---|---:|---|
| sizing_2_101 | 1 | Ошибка выросла; повторное разделение запрещено |
| sizing_4_101 | 2 | Оба альтернативных объединения позволили пройти порог после нового разделения |
| folded_6_211 | 1 | Ошибка выросла; повторное разделение запрещено |
| board_tie_4_101 | 2 | Объединение сохранило качество, полезного нового разделения нет |

Успех `sizing_4_101` считается **одним случаем**, а не двумя независимыми
успехами. Его исходный максимальный unilateral gain был 1,2772% банка при 135
строках стратегии. Объединение почти одинаковых стратегий освободило 15 строк,
оставив ошибку прежней. После разделения другой проблемной группы снова
использованы 135 строк, а ошибка стала **0,0150% банка**. Лимит строк и порог
не повышались. Два альтернативных кандидата дали одинаковые финальные метрики;
тождественность их полных политик здесь не заявляется.

В `sizing_2_101` TV был всего 0,00108, но ошибка выросла с 0,00367% до 0,00770%.
Оба значения ниже 0,5%, однако объединение всё равно отклонено по критерию
неухудшения. В `folded_6_211` TV 0,07366 дал рост с 3,46972% до 3,47029% банка.
Это иллюстрирует, почему фильтр сходства не заменяет пересчёт лучшего ответа.

У общей выигрышной комбинации `board_tie_4_101` удалось освободить 39 строк
без существенной числовой разницы качества, но не было полезного разделения.
Этот простой контроль не означает, что такой запас существует в сложных руках.
У большинства остальных выбранных случаев подходящих почти одинаковых
стратегий при строгом максимальном TV по всем историям не нашлось.

## Проверки и дальнейшее решение

Юнит-тесты проверяют сохранение распределения раздач, объединение одинаковых
стратегий, использование весов рук вместо равных весов групп, восстановление
трассы и её проверку, точную экономию строк, отказ после измеренного ухудшения,
запрет отменяющего объединение разделения, численные параметры и бюджеты.

Результат подтверждает возможность перераспределения на одной малой модели,
но не обосновывает замену основного алгоритма. Предыдущий индексированный путь,
игровые маршруты и теневой флаг сохранены, `live_advice_allowed: false` остаётся
во всех диагностических результатах.

Следующий этап — встроить ограниченную попытку перераспределения в отдельный
экспериментальный цикл с общим бюджетом времени и числом проверок, сохраняя
лучшую проверенную политику при неудаче нового шага. Проверить на всём известном
регрессионном корпусе, отдельно считать новые допуски, регрессии, фактическое
сокращение и временные отказы. После выбора алгоритма нужен новый независимый
корпус. Ошибку выборки широких диапазонов пока не добавлять к ошибке группировки.

```bash
PYTHONPATH=backend backend/.venv/bin/python -m research.benchmark_reallocation > docs/research/group-reallocation-2026-10-24.json
PYTHONPATH=backend backend/.venv/bin/python -m unittest backend.tests.test_group_reallocation
```

Бенчмарк требует заранее собранную native-библиотеку. Юнит-тесты используют
indexed Python CFR+, автоматической компиляции и внешних API нет.

Ограниченный цикл теперь выполнен на всём известном корпусе:
[координатор с контрольными точками](SOLVER_REALLOCATION_CYCLE.md).
Получены три новых допуска без потери прежних; требуется отдельная независимая
проверка зафиксированной версии перед расширением применения.

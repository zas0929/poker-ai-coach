# Объединённый расчёт значений политики и лучшего ответа

Добавлен новый исследовательский путь `train_adaptive_fast` с объединённым
обходом `evaluate_policy`. Прежние `adaptive_strategy.py` и `RiverGame.measure`
сохранены как независимая точка сравнения; хеши зафиксированного корпуса не
изменяются. Игровые маршруты и теневой флаг новый путь не включают.

## Что ускоряется

Раньше неуспешный раунд уточнения выполнял:

1. `game.measure(policy)`: отдельный обход значения политики и лучшего ответа.
2. `action_values(game, policy)`: ещё один `game.measure` для проверки политики,
   затем отдельный обход лучшего ответа с сохранением выгод действий.

Для активных мест это пять обходов, многократно строящих одни и те же веса
скрытых раскладок и читающих те же терминальные выплаты. Один конечный раунд,
где разделение уже не требуется, имел только первую оценку.

Новый обход проверяет полноту и нормировку политики напрямую. Для каждого места
и известной собственной руки он возвращает одновременно значение текущей
политики и значение неограниченного лучшего ответа. В терминале одна и та же
взвешенная выплата используется для обоих. На собственном узле значение
политики усредняется её частотами, а лучший ответ выбирает максимум после
суммирования скрытых раздач. На узлах оппонентов для обоих вычислений используется
один набор весов их достижимости. Одновременно сохраняются Q-векторы, массы и
действия для выбора разделения группы.

Публичные ветки, исходные карты, веса допустимых раздач, выплаты, привязка
стратегий и правило разделения не меняются. Начальные группы, 100 итераций,
бюджеты строк/групп/разделений и порог ≤0,5% также прежние. Промежуточные
значения разных политик не кэшируются и не переиспользуются как актуальные.

Это оптимизация **оценки и подготовки разделений**, не ускорение математического
ядра CFR и не уменьшение полного перебора раздач. В конечном раунде новый путь
также собирает Q-векторы, даже если дальнейшее разделение не понадобится.

## Как сравниваем

[Машиночитаемый отчёт](research/fused-response-2026-10-24.json) содержит два вида
контролей с прежними процессными пределами 45 секунд / 128 MiB:

- Шесть сравнений оценки вместе с данными для разделения, на одной фиксированной
  равномерной политике. Три парных повтора с чередованием порядка методов,
  построение модели исключено из времени. Проверяется точное равенство метрик и
  всех Q-векторов/масс/действий. Отдельный нетаймированный проход считает чтения
  терминальных выплат. Это сравнение полного старого пути уточнения, а не
  одиночного вызова `game.measure`.
- Шесть пар полных адаптивных расчётов: каждый метод в отдельном процессе,
  чередование порядка между случаями, одинаковый вход. Прямая загрузка native
  предварительно прогревается; время построения и запуска процесса исключено.
  По хешам сравниваются вся конечная политика и полный путь уточнения, включая
  выбранные руки, приоритеты разделений, метрики, допуск и причины отказа.

В полном сравнении один запуск каждого метода на случай. Времена описательные,
без доверительных интервалов или гарантии такой же скорости на хостинге.
Процессные отказы сохраняются; недоступная финальная политика не считается
эквивалентной другой по умолчанию.

Юнит-тесты отдельно проверяют точное равенство на равномерных и обученных
политиках для 2–6 мест, коротких стеках, сайд-потах, ничьих и нечётных фишках,
фолднувших местах, нулевой достижимости веток и успешных/отклонённых траекториях.
Контрпример с противоположными выплатами двух скрытых рук проверяет отсутствие
подсматривания: максимум по каждой скрытой руке отдельно дал бы ложную выгоду.

## Повторить

```bash
PYTHONPATH=backend backend/.venv/bin/python -m research.benchmark_fused_response > docs/research/fused-response-2026-10-24.json
PYTHONPATH=backend backend/.venv/bin/python -m unittest backend.tests.test_fused_best_response
```

Бенчмарку требуется отдельно собранная native-библиотека. Юнит-тесты используют
indexed Python CFR+. Новый быстрый путь доступен отдельно в исследовательском
модуле, старые отчёты и манифесты остаются воспроизводимыми на прежней реализации.

## Результаты 24 октября 2026

Во всех четырёх завершённых микроконтролях метрики и данные для разделений
совпали **точно**, без числового допуска. Три парных повтора дали следующие
медианы (оценка вместе с подготовкой разделений):

| Случай | Прежний путь, с | Объединённый путь, с | Отношение времени |
|---|---:|---:|---:|
| dry_2_17 | 0,00379 | 0,00097 | 3,90× |
| flush_3_31 | 0,02114 | 0,00468 | 4,51× |
| folded_6_101 | 0,48187 | 0,10434 | 4,62× |
| sizing_6_101 | 5,04002 | 1,03033 | 4,89× |

Число чтений терминальных выплат в контролях без фолднувшего места уменьшилось
ровно в 5 раз. Для `folded_6_101` — 310 068 → 64 152, примерно в 4,83 раза:
прежний отдельный сбор Q пропускал фолднувшее место, но два вызова `measure`
всё равно считали его выплаты. Проверка фолднувших денег в новом обходе сохранена.

Микроконтроли `prior_sidepot_6_101` и `short_raises_6_101` не завершили три пары
замеров и дополнительный подсчёт чтений за общий лимит 45 секунд. Они записаны
как `timed_out`: для них нет медиан или утверждения о полном сравнении Q-векторов
на равномерной политике. Лимит не увеличивался ради успешного результата.

В четырёх завершённых парах хеши **всех** конечных частот и трассы уточнения
совпали, включая приоритеты и состав разделённых групп. `sizing_6_101` по-прежнему
получил `rejected / no_split_within_budget`, остальные три — `ready` с прежними
метриками. Ускорение не расширяет порог качества и не превращает отказ в допуск.

Несмотря на незавершённый многоповторный микроконтроль сайд-пота, его полный
адаптивный расчёт успешно сравнен по всем итоговым частотам и всем записанным
значениям пути. Это разные нагрузки: микроконтроль дополнительно повторяет
проверки несколько раз и считает чтения выплат.

Оба самых тяжёлых сценария с шестью местами и короткими стеками всё ещё
превысили 45 секунд у обоих методов. Их нельзя включать в среднее ускорение или
считать проверенными по финальной политике. Старт/построение, финальная проверка
через игровой движок и базовый несжатый solve в приведённые времена полного
адаптивного этапа не входят, в отличие от прежнего сквозного holdout-прогона.

## Решение и следующий этап

Быстрый путь оставляем отдельным исследовательским входом с неизменными правилами
допуска. Он даёт измеримое ускорение завершённых расчётов без изменения чисел,
но качество группировки и поддержка полных публичных диапазонов не улучшились.
Старый алгоритм сохранён для регрессионных сравнений; игровые подсказки прежние.

Далее — отдельно профилировать оставшийся тяжёлый путь, особенно перебор
кандидатов разделения и повторное построение строк стратегии для каждого
кандидата. Следующую оптимизацию также сравнивать по составу разделений,
политикам, метрикам и отказам. После устранения затрат — улучшать разделение
групп для 4–6 мест и проводить новую независимую оценку, не ослабляя порог.

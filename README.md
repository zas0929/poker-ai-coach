# Poker AI Coach

Private rooms are available at [localhost:3000/friends](http://localhost:3000/friends).
Create a table for 2-6 friends, share an invitation, confirm readiness and deal.
Cards are filtered on the server; seats restore after reconnect. This is a local
preview with virtual chips and SQLite-backed rooms. Hands and seats survive
server restarts. The host can configure stacks, blinds and turn time before the
first deal. Hosting preparation is documented in [docs/HOSTING.md](docs/HOSTING.md).
See [docs/ROOMS.md](docs/ROOMS.md) for setup, protocol and current limitations.

Completed hands appear in **Your hand history** inside the room. Open a hand to
replay each decision, review net chips and inspect main/side-pot payouts. The
archive requires your seat token and follows the same private-card rules as live play.

[Practice & decisions](http://localhost:3000/practice) saves your AI-table choices
and offers call-price and legal-action exercises, including your own past spots.
Answers, progress and the personal journal survive restarts. See
[docs/TRAINING.md](docs/TRAINING.md) for grading, access and current limitations.

## How the trainer works today

The trainer uses a **rule-based poker bot, probability calculations and templated
explanations**. There is no connected LLM, trained neural policy or GTO solver.
“AI” in the interface currently refers to this algorithmic opponent and coach.
An LLM explanation layer is a future idea, not an implemented feature.

The engine infers heuristic opponent ranges from public actions, estimates equity,
and selects advice using fixed thresholds. Bots use preflop hand categories and
postflop recommendations; the coach formats the results into predefined text.
A decision that “matches coach” agrees with that heuristic, not a proven optimal
strategy. Calculated call EV excludes future betting and rake; side-pot call EV
is unavailable at tables with more than two dealt players.

See **[Как работает тренер: расчёты, бот и ограничения](docs/TRAINER.md)** for the
full flow, formulas, bot rules, performance costs and relevant source files.

## Current range analysis

Equity uses weighted legal opponent combinations, excluding the analyzing player's
cards and the visible board. Hidden opponent cards and the shuffled deck are never
used. Blinds alone leave a uniform range; voluntary actions update relative weights.
Preflop weights account for heads-up position and prior raises. Postflop weights
use made hands and draws on the board visible at the time of each action; checks
are weak evidence and aggressive ranges retain possible bluffs.

This is an **uncalibrated educational heuristic**, not GTO or an exact model of the
AI opponent. Bet sizing, stack depth, rake and opponent-specific tendencies do not
adjust range weights yet. Against one live opponent, river equity is exact *for the assumed range*;
earlier streets use reproducible Monte Carlo samples. The displayed 95% sampling
bound covers simulation noise only, not errors in the assumed range. Effective
combos are `(sum(weights) ** 2) / sum(weight ** 2)`, a concentration measure rather
than a list of hands that remain possible. Hand-class tags show total weight over
available suit combinations, not optimal opening charts.

Call EV assumes no future betting and no rake, and excludes an uncallable overbet
when the player is short-stacked. Bet/raise advice still uses equity thresholds;
the application does not calculate all action EVs. The Coach Panel labels matching
decisions as “matches coach” rather than claiming optimal play. Coaching text is
currently generated by templates; the LLM endpoint remains on the MVP roadmap.

Source files for this update: `range_service.py`, `equity_service.py`, and
`tests/test_ranges.py`. The analysis API adds `opponent_range`, `equity_method`,
`equity_samples`, and `equity_sampling_error` to its existing response.

## MVP Plan

1. Heads-up Texas Hold'em hand flow.
2. Start a new hand with hero and AI opponent hole cards.
3. Track street, board, pot, stacks, blinds, current player, and action history.
4. Add player actions: fold, check, call, bet, raise.
5. Add hand evaluator and showdown resolution.
6. Add Monte Carlo equity against simple opponent ranges.
7. Add pot odds and EV calculations.
8. Add decision engine with recommended action and confidence.
9. Add LLM Explain Decision endpoint for Coach Panel.
10. Build a clean poker table UI with Coach Panel as the primary learning surface.

## Backend Start

Run from `backend/`:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload
```

Start a hand (the frontend creates a profile automatically; direct API clients first
POST `/api/training/profiles` and use the returned token):

```bash
curl -X POST http://localhost:8000/api/hand/start \
  -H 'Authorization: Bearer <training-profile-token>'
```

Analyze the hero decision:

```bash
curl http://localhost:8000/api/hand/analyze
```

Apply a player action:

```bash
curl -X POST http://localhost:8000/api/hand/action \
  -H "Content-Type: application/json" \
  -d '{"player_id":"hero","action":"call"}'
```

Advance after betting action is closed:

```bash
curl -X POST http://localhost:8000/api/hand/advance
```

Manual street endpoints are still available, but they only work after the current betting round is closed:

```bash
curl -X POST http://localhost:8000/api/hand/flop
curl -X POST http://localhost:8000/api/hand/turn
curl -X POST http://localhost:8000/api/hand/river
```

Run backend regression tests:

```bash
PYTHONPATH=. python3 -m unittest discover -s tests
```

## Frontend Start

Run from `frontend/` after the backend is running:

```bash
npm install
npm run dev
```

Open `http://localhost:3000`.

The UI shows a hand result after fold or showdown, including winners, pot awarded, and each player's final hand category.
Villain actions and street advancement are automated through `POST /api/hand/auto-play`, using the current decision engine recommendation.
The AI opponent decision layer lives in `backend/app/services/ai_opponent.py`; it starts with a balanced profile, preflop hand categories, and postflop equity-based decisions.

## Multiplayer roadmap and betting rules

See [docs/ROADMAP.md](docs/ROADMAP.md) for the private 2–6 player release plan.
The current 2–6 player API includes `betting` with legal actions and inclusive size
bounds. Raise amounts are total street bets; fractional amounts and oversized

## Multiway training tables

`POST /api/hand/start?player_count=6` creates a training table with five AI
opponents. Without a count, `/start` resumes the current table or preserves its
size for the next hand. A different size is accepted only after a hand ends and
starts a new training session. The browser's Seats selector now controls actual
players, not decorative empty seats.

The engine tracks `contributions` across all streets, resolves main/side pots in
`result.pots`, keeps folded contributions as dead money, and refunds unmatched
bets. Each hand has a private, non-serialized deck. Training profiles have separate in-memory hand states, but their operations are
serialized by a shared lock. Private rooms with human players are available at
`/friends`; see [docs/ROOMS.md](docs/ROOMS.md).

Multiway equity samples every live opponent jointly and rejects card collisions.
It includes split pots and ignores hidden AI holdings. It does not calculate
side-pot call EV: `call_ev_available=false` explicitly marks that omission for
any table with more than two dealt players, even if only two remain live.
The displayed price proxy and recommendations are educational heuristics, not
solver-derived action EV comparisons. Sample count and sampling-only uncertainty
remain visible. Expand each opponent's range to inspect its assumptions.

The offline prototype preserves folded seats/dead contributions and can build

The wider all-seats-uncertain research suite measures quality, isolated-process

An opt-in indexed CFR+ traversal preserves the reference policies while reducing

Expanded range budgets are opt-in (default remains 64 raw combinations), with
a separate time/RSS-monitored research runner. Successes, timeouts and quality

An explicitly built C++17 research kernel and compact float64 payoffs are available
via `cfr_plus_native` / `utility_storage='compact'`. No runtime auto-compilation
or production trainer switch occurs. See [docs/SOLVER_NATIVE.md](docs/SOLVER_NATIVE.md).

The public river adapter also reconstructs decisions after checks, wagers, calls,
raises and folds. See [docs/SOLVER_RIVER_CONTINUATION.md](docs/SOLVER_RIVER_CONTINUATION.md)
for replay rules, chip accounting and paired Python/native controls. This remains
offline research with explicit public range subsets.

Wider public mid-river controls now measure isolated-process latency, RSS and
exact best-response quality with uncertainty at every live seat. All 16 fixed
controls passed their bounded-game gate; this does not validate full-range NLHE
or public range calibration. See [docs/SOLVER_MIDRIVER_RANGES.md](docs/SOLVER_MIDRIVER_RANGES.md).

An offline comparison now probes the current coach and a controlled same-subset
equity variant against bounded river continuations, preserving exact recommended
sizes. See [docs/SOLVER_COACH_COMPARISON.md](docs/SOLVER_COACH_COMPARISON.md)
for conditional EV, scope limits and the reproducible 44-hand corpus. Live advice
is unchanged.

A versioned offline admission contract now records model/version identity,
quality, tree limits, timing and refusal reasons. Candidates are emitted only
for admitted research results; live advice remains disabled. See
[docs/SOLVER_ANALYSIS_CONTRACT.md](docs/SOLVER_ANALYSIS_CONTRACT.md) for budgets,
stale-result checks and the real-process controls.

A bounded offline shadow executor now schedules isolated analyses without waiting
for them, shares in-flight requests, discards stale deliveries and cancels orphaned
work. It has no game-route integration. See
[docs/SOLVER_SHADOW_EXECUTOR.md](docs/SOLVER_SHADOW_EXECUTOR.md) for queue/retention
limits, lifecycle, cancellation and real-process controls.

The trainer has a disabled-by-default local shadow hook. Explicit per-decision
plans are prepared off the request path; current hints remain unchanged and
stale observations are discarded. See [docs/TRAINER_LOCAL_SHADOW.md](docs/TRAINER_LOCAL_SHADOW.md)
for the opt-in flags, strict plan format, limited coverage and native end-to-end control.

For local diagnostic runs on unlisted river decisions, an explicit seeded subset
policy and loopback-only launcher are available. The policy failed range-stability
controls and must not replace current advice. See
[docs/SOLVER_PUBLIC_SUBSET_POLICY.md](docs/SOLVER_PUBLIC_SUBSET_POLICY.md) for the
one-command flag, configuration, anchoring assumptions and paired sensitivity report.

A multi-seed, multi-width river comparison now tests category/blocker representatives
against uniform subsets on 12 decision/own-hand probes. More repeatable actions did
not improve reference EV diagnostics; neither selection is validated for live advice.
See [docs/SOLVER_RANGE_STABILITY.md](docs/SOLVER_RANGE_STABILITY.md) for the 168 solves,
matched-population comparisons, reference disagreement and next abstraction work.

An offline exact river range quotient now merges only hands with identical
blocker and showdown relations, preserving group mass. Seventeen full-vs-compressed
controls verified legal/illegal lineups, terminal payouts and lifted-policy best
responses. Compression is conservative and often absent; live advice is unchanged.
See [docs/SOLVER_EXACT_RANGE_QUOTIENT.md](docs/SOLVER_EXACT_RANGE_QUOTIENT.md).

A tree-free audit of wide public ranges found no exact contraction in all 20
full-support controls (1081 hands per live seat): blockers alone distinguish every
hand. The audit does not run CFR or admit advice. See
[docs/SOLVER_WIDE_RANGE_AUDIT.md](docs/SOLVER_WIDE_RANGE_AUDIT.md) for 27 bounded
controls and the next strategy-abstraction experiment preserving original deals.

An offline strategy-abstraction prototype now ties strategy rows while retaining
all original deals and payoffs. Thirty small full-game controls and three longer
failure probes found that simple category/equity bins are not reliable enough;
quality is measured by unrestricted best responses after lifting to original hands.
See [docs/SOLVER_STRATEGY_ABSTRACTION.md](docs/SOLVER_STRATEGY_ABSTRACTION.md).

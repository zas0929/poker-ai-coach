# Poker AI Coach

Private rooms are available at [localhost:3000/friends](http://localhost:3000/friends).
Create a table for 2-6 friends, share an invitation, confirm readiness and deal.
Cards are filtered on the server; seats restore after reconnect. This is a local
preview with virtual chips and SQLite-backed rooms. Hands and seats survive
server restarts. The host can configure stacks, blinds and turn time before the
first deal. Internet hosting is a later stage.
See [docs/ROOMS.md](docs/ROOMS.md) for setup, protocol and current limitations.

Completed hands appear in **Your hand history** inside the room. Open a hand to
replay each decision, review net chips and inspect main/side-pot payouts. The
archive requires your seat token and follows the same private-card rules as live play.

[Practice & decisions](http://localhost:3000/practice) saves your AI-table choices
and offers call-price and legal-action exercises, including your own past spots.
Answers, progress and the personal journal survive restarts. See
[docs/TRAINING.md](docs/TRAINING.md) for grading, access and current limitations.

Texas Hold'em AI Coach is a poker training app inspired by the Chess AI Coach architecture: a deterministic analysis backend, a focused frontend table, and an AI coach panel that explains decisions in natural language.

The core idea is hybrid:

- Poker engine does the math: hand state, legal actions, hand evaluation, Monte Carlo equity, pot odds, EV, ranges, and decision recommendations.
- LLM coach explains the result: why a fold, call, bet, or raise makes sense in the current spot.

The LLM should not guess poker strategy directly. It receives structured analysis from the engine and turns it into clear coaching.

## Current range analysis

Equity uses weighted legal opponent combinations, excluding the analyzing player's
cards and the visible board. Hidden opponent cards and the shuffled deck are never
used. Blinds alone leave a uniform range; voluntary actions update relative weights.
Preflop weights account for heads-up position and prior raises. Postflop weights
use made hands and draws on the board visible at the time of each action; checks
are weak evidence and aggressive ranges retain possible bluffs.

This is an **uncalibrated educational heuristic**, not GTO or an exact model of the
AI opponent. Bet sizing, stack depth, rake and opponent-specific tendencies do not
adjust range weights yet. On the river equity is exact *for the assumed range*;
earlier streets use reproducible Monte Carlo samples. The displayed 95% sampling
bound covers simulation noise only, not errors in the assumed range. Effective
combos are `(sum(weights) ** 2) / sum(weight ** 2)`, a concentration measure rather
than a list of hands that remain possible. Hand-class tags show total weight over
available suit combinations, not optimal opening charts.

Call EV assumes no future betting and no rake, and excludes an uncallable overbet
when the player is short-stacked. Bet/raise advice still uses equity thresholds;
the application does not calculate all action EVs. The Coach Panel labels matching
decisions as “matches coach” rather than claiming optimal play. Coaching text is
currently generated by templates; the LLM endpoint remains on the MVP roadmap.

Source files for this update: `range_service.py`, `equity_service.py`, and
`tests/test_ranges.py`. The analysis API adds `opponent_range`, `equity_method`,
`equity_samples`, and `equity_sampling_error` to its existing response.

## MVP Plan

1. Heads-up Texas Hold'em hand flow.
2. Start a new hand with hero and AI opponent hole cards.
3. Track street, board, pot, stacks, blinds, current player, and action history.
4. Add player actions: fold, check, call, bet, raise.
5. Add hand evaluator and showdown resolution.
6. Add Monte Carlo equity against simple opponent ranges.
7. Add pot odds and EV calculations.
8. Add decision engine with recommended action and confidence.
9. Add LLM Explain Decision endpoint for Coach Panel.
10. Build a clean poker table UI with Coach Panel as the primary learning surface.

## Backend Start

Run from `backend/`:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload
```

Start a hand:

```bash
curl -X POST http://localhost:8000/api/hand/start
```

Analyze the hero decision:

```bash
curl http://localhost:8000/api/hand/analyze
```

Apply a player action:

```bash
curl -X POST http://localhost:8000/api/hand/action \
  -H "Content-Type: application/json" \
  -d '{"player_id":"hero","action":"call"}'
```

Advance after betting action is closed:

```bash
curl -X POST http://localhost:8000/api/hand/advance
```

Manual street endpoints are still available, but they only work after the current betting round is closed:

```bash
curl -X POST http://localhost:8000/api/hand/flop
curl -X POST http://localhost:8000/api/hand/turn
curl -X POST http://localhost:8000/api/hand/river
```

Run backend regression tests:

```bash
PYTHONPATH=. python3 -m unittest discover -s tests
```

## Frontend Start

Run from `frontend/` after the backend is running:

```bash
npm install
npm run dev
```

Open `http://localhost:3000`.

The UI shows a hand result after fold or showdown, including winners, pot awarded, and each player's final hand category.
Villain actions and street advancement are automated through `POST /api/hand/auto-play`, using the current decision engine recommendation.
The AI opponent decision layer lives in `backend/app/services/ai_opponent.py`; it starts with a balanced profile, preflop hand categories, and postflop equity-based decisions.

## Multiplayer roadmap and betting rules

See [docs/ROADMAP.md](docs/ROADMAP.md) for the private 2–6 player release plan.
The current 2–6 player API includes `betting` with legal actions and inclusive size
bounds. Raise amounts are total street bets; fractional amounts and oversized
requests are rejected. A repeated `/start` resumes a live training hand.

## Multiway training tables

`POST /api/hand/start?player_count=6` creates a training table with five AI
opponents. Without a count, `/start` resumes the current table or preserves its
size for the next hand. A different size is accepted only after a hand ends and
starts a new training session. The browser's Seats selector now controls actual
players, not decorative empty seats.

The engine tracks `contributions` across all streets, resolves main/side pots in
`result.pots`, keeps folded contributions as dead money, and refunds unmatched
bets. Each hand has a private, non-serialized deck. API operations on the one
in-memory training session are serialized; independent rooms and human players
are still the next milestone.

Multiway equity samples every live opponent jointly and rejects card collisions.
It includes split pots and ignores hidden AI holdings. It does not calculate
side-pot call EV: `call_ev_available=false` explicitly marks that omission for
any table with more than two dealt players, even if only two remain live.
The displayed price proxy and recommendations are educational heuristics, not
solver-derived action EV comparisons. Sample count and sampling-only uncertainty
remain visible. Expand each opponent's range to inspect its assumptions.
